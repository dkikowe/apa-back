# Архитектура и план на 21 день

Клиент React/Vite вызывает REST API Express по тому же origin. API хранит сессии, участников, платежи, документы и журнал изменений в MongoDB replica set. Документы лежат в закрытом S3; браузер получает ссылки на 120 секунд. Отдельный worker берёт задания OCR атомарно из MongoDB, читает локально PDF/Tesseract и записывает только найденные поля. Обнаруженные значения никогда не сохраняются как участник или платёж без проверки оператора.

- [apa-front](https://github.com/dkikowe/apa-front): страницы, формы, загрузка документа, состояние запросов TanStack Query.
- `shared/domain.ts`: входные схемы, даты, денежные единицы, названия.
- `server/app.ts`: защищённый REST API и транзакции.
- `server/models.ts`: модели и индексы.
- `server/services/members.ts`: серверные фильтры, агрегация платежей и пагинация.
- `server/services/reports.ts`: статистика, отчёты и XLSX.
- `server/services/storage.ts`: единственная точка доступа к S3.
- `server/services/ocr.ts`, `server/worker.ts`: локальное распознавание и очередь.
- `tests`: бизнес-правила и API с настоящим временным MongoDB replica set.

День 1–3: согласовать понятность интерфейса с оператором, проверить реальные повседневные сценарии на вымышленных данных. День 4–7: авторизация, участники, поиск, восстановление, тесты. День 8–11: закрытое хранилище, локальные языковые модели и набор разрешённых контрольных документов; замер качества OCR. День 12–14: частичные платежи, дубликаты, исправления, транзакции. День 15–17: прочие операции, сводки, отчёты, Excel. День 18–19: нагрузочные проверки на 20 000 участников и приёмка оператором. День 20–21: согласованное размещение, TLS, резервные копии, пробное восстановление, запуск.

Серверный код находится в этом репозитории, интерфейс — в apa-front. 21 день — план внедрения и приёмки, а не заявление о проведённых нагрузочных/полевых испытаниях.

## Важные правила

Суммы в базе — целые тиыны; 6 487 ₸ = 648700. Год жарны (`year`) отличается от даты фактического платежа (`paymentDate`). Статусы участников используют год жарны. Общая финансовая сводка использует фактическую дату поступления и включает деньги архивных участников. Архивирование не удаляет историю. Платежи не копируются в коллекцию иных финансовых операций. Переплаты не уменьшают остаток нового года.

Изменения участника, платежа и финансовой операции вместе с AuditLog пишутся одной MongoDB транзакцией. Поэтому standalone MongoDB не подходит. Уникальный multikey-индекс `dedupeKeys` защищает от одновременной записи одного чека; явное подтверждение дубликата сохраняется в журнале изменения (добавить оператору проверку назначения по истории). Поля интерфейса проверяются сервером. Поиск — префикс каждого слова ФИО либо префикс нормализованного телефона.

Выгрузка участников читает весь результат курсором на сервере; фильтр оплаты применяется после агрегации. До 20 000 строк формируются в памяти ExcelJS. Точные лимиты памяти/времени надо подтвердить на выбранном сервере. База индексирует архив/регион/дату рождения, токены поиска, телефон, имя, платежи по участнику/году и даты операций.
